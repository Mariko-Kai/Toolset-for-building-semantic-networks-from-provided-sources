# Refactor: Remediation Roadmap (пост-Этап-5)

> **Статус файла — ИСТОРИЯ (Refactor-журнал), не документация.**
> Документация (`docs/`) описывает *текущее состояние* проекта. Этот файл фиксирует
> *процесс* приведения проекта к заявленным целям и принятые по ходу решения.
> Companion к `docs/REFACTOR_SPEC.md` (который логически тоже относится сюда и может
> быть перенесён в `refactor/` на Этапе B).
>
> Источник: код-ревью от **2026-05-31** (4 параллельных ревью-агента + ручная проверка
> `ruff`/`pytest`/diff). Решения заказчика по итогам ревью зафиксированы ниже.

## Цели (Definition of Done)
Конечное состояние = то, что было заявлено в исходном запросе на код-ревью:
1. **Нет легаси.** `git ls-files` без артефактов/дубликатов/scratch; CI-gate гигиены держит инвариант.
2. **Документация всегда актуальна.** Достигается НЕ ручным сопровождением прозы, а тем, что
   документация — *генерируемое представление текущего состояния*, которое поддерживает
   **оркестратор** в том же gate, где он подтверждает «патч применён, регрессии нет, тесты зелёные».
3. **Самоэволюция несущая.** `capabilities.produce()` реально производит представления
   (latex/lean/**doc**); `missing_representations` рождает задачи; `LLMIncidentHandler` лечит
   в проде за human-gate; переносимость подтверждена пилотом.

## Этап A — Стабилизация рабочего дерева (разблокировать коммит)
**Цель:** грязный незакоммиченный changeset снова проходит `ruff`/`pytest` и безопасно коммитится атомарными порциями.

- **A.1 Развилка `enrichment_coordinator`.** Факт: файл идентичен удалённому `ollama_wrapper.py`
  на 99.74% (отличие — параметр `echo`), докстринг гласит «Ollama Wrapper v2». Решение для A:
  оформить как честный модуль-драйвер (исправить докстринг). Реальная декомпозиция монолита
  на skills+coordinator — отдельная работа (Этап F/G), не блокирует стабилизацию.
- **A.2 ruff (6 ошибок в новых файлах):** `import subprocess` в `entity_manager.py:121` (`F821` —
  реальный баг, пункт меню падал бы `NameError`); снять 5×`F401`.
- **A.3 Транзакционная целостность skills:** `PRAGMA defer_foreign_keys=ON` вместо
  `foreign_keys=OFF` (`rename_skill.py`); файловые операции — часть контракта успеха
  (скилл не возвращает `True` при проваленном move/unlink); `db.init_db()` в `entity_manager`,
  иначе `Incident` молча теряется (нарушение Fail-Safe).
- **A.4 Тесты:** негативные/rollback-кейсы skills + покрытие `entity_manager` (диспетчер, gate
  `db.validate()`, регистрация инцидента).
- **Приёмка:** `ruff check .` чист; `pytest` зелёный; changeset разбит на тематические коммиты.

## Этап F — Документация как генерируемое представление, поддерживаемое оркестратором
**Цель (объединяет бывшие D+E+F):** документация перестаёт быть рукописной прозой и становится
*представлением текущего состояния*, которое генерируется и поддерживается оркестратором как
инвариант. Включает практическую реализацию отображения проект→документация.

### F.1 Отображение «документация ↔ символы кода» (практика бывш. Этапа E)
Переиспользуем собственный примитив проекта: граф `entity_dependency` + backlinks `get_used_by`.
- **Якоря:** reference-доки уже заякорены через mkdocstrings `:::`; нарративные секции получают
  машиночитаемый якорь `<!-- doc-ref: api=... | routes=... | enum=... | table=... -->`.
- **Поверхность кода (`code_surface`):** стабильные ID символов + контент-хеш —
  `api:Qualified.Name` (через `inspect.signature`), `route:METHOD /path` (`app.routes`),
  `schema:table.column`/enum-токен (парс `schema.py`/`models.py`), `tree:content/defs/` (glob),
  `macro:\Name` (сканер `macro_compiler`).
- **Таблицы (форма = `entity_dependency`):**
  `code_surface(symbol_id PK, kind, content_hash, last_seen_commit)`,
  `doc_node(doc_id PK, path, anchor, content_hash)`,
  `doc_dependency(doc_id FK, symbol_id, PK(doc_id,symbol_id))`.
- **Детектор устаревания:** пересчёт `code_surface` → diff хешей → join к `doc_dependency`:
  changed→кандидат-устаревания; removed→битая ссылка (hard fail); added-без-ссылки→недокументированное.
- **CLI:** `python -m pipeline.docsync check` → отчёт формы `ValidationReport` (doc:секция, символ, причина).

### F.2 Документация как capability (несущая генерация)
- Зарегистрировать `capability: document`, продюсер = существующий NL-синтез (`generate_answer`/`nl_desc`).
- `missing_representations` для символа = «нет описания» → оркестратор делает `produce("document", symbol)`.
- Это чинит «пустые capabilities» (Часть IV ревью) и реализует переопределение задачи «доки».

### F.3 Оркестратор владеет документацией (gate, бывш. п.3 исследования)
- Слить «два мира оркестрации»: цикл лечения (dual-queue в `main()`) и мутирующие skills
  (delete/rename/change_type) ходят **через** `Orchestrator` — иначе gate можно обойти.
- Расширить определение «изменение подтверждено» до конъюнкции инвариантов:
  `confirmed ⟺ applied(patch) ∧ pytest_green ∧ ruff_clean ∧ docsync_clean(diff)`
  (новые узлы `TestNode`/`LintNode`/`DocSyncNode`).
- Новый тип отклонения `DOC_DRIFT`; `PatchPlan` получает поле `doc_edits`; `auto_applicable`
  остаётся `False` (человек подтверждает), но gate **отказывает**, пока staleness-множество не
  закрыто doc-правками. `LLMIncidentHandler` оживает в проде: черновит doc-правки на `DOC_DRIFT`.
- Персистенция: `DOC_DRIFT`-события в `store`; `/monitor` показывает «docs pending».
- **Приёмка:** структурное изменение через оркестратор физически не подтверждается без синхронной
  валидной doc-правки; `mkdocs --strict` + тесты-guards (фантомные методы/роуты/запрещённые токены) зелёные.

## Этап G — Несущая самоэволюция
**Цель:** самоэволюция перестаёт быть костюмом.
- Несущие producer'ы `synth_latex`/`to_lean` (функции уже есть — зарегистрировать); `has_capability`
  различает «декларировано» vs «производимо».
- Параметризовать ядро `DomainPack`'ом (`_check_kind` из `entity_kinds`, не хардкод `def/prop`);
  обобщить Lean-специфичные колонки (`lean_status/decl/path`) до namespace формализации по `target_language`.
- Реальный миграционный раннер по `SCHEMA_VERSION`.
- End-to-end пилот `logic_coq` на мини-корпусе (переиспользование ядра без правок).
- **Eval-harness** (`tests/bench/`): % сущностей с `lean_status=valid`, recall извлечения,
  стоимость/латентность LLM — измеримый градиент «эволюции».
