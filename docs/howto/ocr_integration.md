# Оценка внедрения полноценного OCR

> Исследование по состоянию на Этап 3. Вывод: **реального OCR в проекте нет** —
> есть аргумент-заглушка и отдельная утилита рендеринга. Полноценное внедрение —
> **умеренная задача**, архитектура к нему хорошо готова.

## Что есть сейчас (факты, с привязкой к коду)

| Компонент | Состояние |
|---|---|
| Извлечение текста PDF | Только встроенный текстовый слой: `doc[i].get_text("text")` в `ensemble_extractor.py` и `search_index.py`. **Сканы/картиночные PDF дадут пусто.** |
| PDF → изображения | `pipeline/pdftoimages/pdf_to_images.py` (рендер через `get_pixmap`) — **standalone-утилита**, в конвейер не подключена. |
| `--cv-model` | Парсится один раз (`ensemble_extractor.py:687`), **далее нигде не используется** — чистая заглушка (`glm-ocr`/`qwen3-vl` только в README). |
| `--ocr-pages` | Лишь **переопределение страниц** для фазы поиска (`ensemble_extractor.py:831+`), OCR не запускает. |
| Vision в `model_manager` | **Нет**: ни `image`/`base64`, ни мультимодальных запросов — все провайдеры текстовые. |
| OCR-библиотеки | Не установлены (нет tesseract/easyocr/paddle/rapidocr); `pillow` есть, но не задействован. |

## Что нужно для полноценного OCR (точки интеграции)

Поток: **страница без текстового слоя → рендер в изображение → vision-модель → текст → существующий конвейер экстракции.**

1. **Рендер страницы в изображение** — *тривиально, код уже есть.*
   Переиспользовать `pdf_to_images.render_pages` / `page.get_pixmap()`. Точка: рядом с
   `extract_context_window()` в `ensemble_extractor.py`.

2. **Vision в `ModelManager`** — *главная недостающая часть, средняя сложность.*
   Добавить в абстракцию `ModelStrategy` опциональный путь с изображением, напр.
   `generate_content(prompt, images=[bytes], ...)`. Реализовать по провайдерам:
   - **Ollama**: `/api/generate` принимает поле `images` (base64) для мультимодальных
     моделей (llava/qwen-vl) — добавить кодирование и поле в payload (`OllamaStrategy`).
   - **Gemini**: `types.Part.from_bytes(data, mime_type='image/png')` в `contents`.
   - **OpenAI**: сообщение с `{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}`.
   Это укладывается в текущий strategy-паттерн — без слома существующих текстовых вызовов.

3. **Маршрутизация роли `cv`/`ocr`** — *низкая сложность.*
   Завести роль `cv` в `ModelManager` (как `extract`/`synth`/`lean`), прокинуть
   реально используемый `--cv-model` через `config.resolve_module_config` (сейчас он
   только передаётся между процессами и игнорируется).

4. **Детектор «сканированной» страницы** — *низкая сложность.*
   Эвристика: если `get_text` по странице даёт < N символов (или низкую плотность
   текста) — помечаем как картиночную и пускаем через vision-OCR. Иначе — текстовый слой.

5. **Слияние результатов и устойчивость** — *средняя сложность.*
   Гибридные PDF (часть текстом, часть сканом); таймауты/ретраи vision-вызова
   (переиспользовать `ModelError`/backoff из Этапа 1); кэш изображений как у `pdf_text`.

## Оценка сложности

**Умеренная (≈3–6 дней до продакшн-качества.)** Дешевле, чем кажется, потому что:
- рендер изображений уже реализован;
- `ModelManager` имеет чистую абстракцию провайдеров — нужен лишь image-путь;
- конвейер экстракции имеет понятную точку врезки (там, где сейчас берётся текстовый слой);
- ретраи/таймауты/процессы уже укреплены на Этапах 1.

**Главные блокеры:** (1) отсутствие vision-пути в `model_manager`; (2) `cv_model`
не прокинут до реального вызова; (3) нет детектора сканов; (4) нет тестов.

## Рекомендуемый первый шаг (MVP, ~1 день)
Добавить `OllamaStrategy.generate_content(..., images=[png_bytes])` (поле `images`
в `/api/generate`), роль `cv` в `ModelManager`, и в `ensemble_extractor` — ветку:
«если текст страницы пуст → рендер `get_pixmap` → vision-OCR через роль `cv` →
полученный текст идёт дальше как обычный extracted text». Это даёт сквозной OCR на
одном провайдере; Gemini/OpenAI добавляются по тому же интерфейсу.

> Замечание по архитектуре: vision-OCR — естественный кандидат на «capability» из
> Этапа 5 (реестр возможностей). Если внедрять после Этапа 4, OCR можно оформить как
> подключаемую стратегию извлечения, а не зашивать в `ensemble_extractor`.
