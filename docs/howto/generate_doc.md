# Генерация первого документа

Это руководство показывает, как извлечь математические сущности из страниц учебника с помощью LLM-агента.

---

## Предварительные условия

- Проект развёрнут ([Развёртывание](deployment.md))
- В `.env` указан действующий `GEMINI_API_KEY`
- Учебники размещены в `Books/`

---

## Шаг 0: Поиск страницы в источниках

Поиск осуществляется строго по приоритетам из `sources/_registry.yaml` для соответствующей дисциплины.

```bash
python tools/search_index.py --query "аналитическая функция"
```

Алгоритм поиска:

1. **Морфологический стемминг.** Термин разбивается на корни слов (например, `"аналитическая функция"` → `["аналитическ", "функци"]`). Это позволяет находить термин в любом падеже (именительном, творительном и т.д.).
2. **Мультиязычный перевод.** Термин автоматически переводится RU↔EN через LLM. Поиск ведётся одновременно по корням на обоих языках.
3. **Частичное соответствие.** Совпадение засчитывается, если все корни найдены на одной странице в пределах одного абзаца.
4. **Приоритет источников.** Скрипт проходит учебники строго по `priority` из `_registry.yaml` и останавливается на первом совпадении.

---

## Шаг 1: Конвертация PDF → Изображения

```bash
python tools/pdftoimages/pdf_to_images.py "Books/Zorich V.A. - Mathematical Analysis I - (RU) - [2012].pdf" --pages 40-45
```

Результат: изображения страниц появятся во временной директории.

---

## Шаг 2: Запуск агента-экстрактора

```bash
python tools/agent/agent.py --images <путь_к_изображениям>
```

Агент:

1. Загружает системный промпт из `docs/prompts/content_extractor.md`
2. Отправляет изображения страниц в Gemini API
3. Генерирует stub-файлы `.tex` с метаданными
4. Сохраняет их в соответствующие директории `content/`
5. Обновляет `content/master.tex` (добавляет `\input{}`)

---

## Шаг 2.1: Оценка достаточности источника (`INSUFFICIENT_SOURCE`)

После извлечения агент оценивает, достаточно ли извлечённого материала для формирования канонической записи.

- Если извлечённое определение **достаточно** для формализации → переход к Шагу 3.
- Если **недостаточно** (определение нестрогое, термин упомянут в бытовом смысле, или отсутствует) — агент возвращает код `INSUFFICIENT_SOURCE` и **переходит к следующему учебнику** по приоритету из `_registry.yaml` (возврат к Шагу 0).
- Если все источники исчерпаны — ошибка `SourceNotFoundError`.

!!! warning "Важно"
    Перед переходом к следующему источнику агент обязан проверить **все** найденные страницы в текущем источнике, а не только первую.

## Шаг 3: Проверка результатов

1. Убедитесь, что новые `.tex` файлы появились в `content/objects/`, `content/properties/` и т.д.
2. Каждый файл должен содержать метаданные:
   ```latex
   % entity-id: obj-neighborhood
   % entity-type: object
   % defined-in: zorich-1, p. 42
   ```
3. Скомпилируйте `master.tex` для проверки:
   ```batch
   build.bat
   ```

---

## Шаг 4: Заполнение формулировок

Stub-файлы содержат только шаблонную структуру. Заполните тело определения:

```latex
\begin{object}[Окрестность точки]
\label{entity:obj-neighborhood}
% 1. ОБЪЯВЛЕНИЕ ТИПОВ
\mForall{a \in \entityref{obj-real-numbers}{\mReal}}
\mForall{\varepsilon > 0}

% 2. ТЕЛО ОПРЕДЕЛЕНИЯ
\entityref{obj-neighborhood}{\text{Окрестность}} \; U(a, \varepsilon)
\mDefIff
\mSet{x \in \mReal \mid |x - a| < \varepsilon}
\end{object}
```
