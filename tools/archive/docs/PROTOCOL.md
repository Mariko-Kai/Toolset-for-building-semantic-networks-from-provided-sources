# Протокол заполнения канонической базы знаний (Content Layer)

Этот документ описывает стандартную процедуру (SOP) по преобразованию математических текстов из учебников в строгий формат графа зависимостей в директории `content/`.

---

## 1. Концепция "Семантического Токена"

**Фундаментальное правило:** Единица смысла = Единица разметки.

Мы не разбиваем визуально целостные математические идиомы на части, если они обозначают одну сущность.

### Классификация Токенов

| Тип токена | Описание | Пример (LaTeX) | Правило разметки (`\entityref`) |
|---|---|---|---|
| **Atomic Constant** | Глобальная константа или множество | `$\mathbb{R}, \pi, \varnothing$` | Оборачивается весь символ. `\entityref{obj-real-numbers}{\mathbb{R}}` |
| **Variable** | Переменная, обозначающая объект | `$x, f, \varepsilon$` | Не оборачивается. Ссылка ставится на её ТИП при объявлении квантора. `\forall \entityref{obj-function}{f}` |
| **Idiom / Modifier** | Сущность, созданная модификацией символа | `$f^{-1}, f', x_n, \bar{A}$` | Оборачивается весь модифицированный блок. `\entityref{op-inverse}{f^{-1}}` |
| **Operator** | Бинарный/унарный знак операции | `$+, \cup, \times, \circ$` | Оборачивается только знак. `A \mathbin{\entityref{op-union}{\cup}} B` |
| **Wrapper** | Оператор, оборачивающий аргументы | `$\lim, \int, \sum$` | Оборачивается символ оператора. `\entityref{op-limit}{\lim}_{x \to a}` |

## 2. Алгоритм Разрешения Перегрузок (Signature Resolution)

Генератор контента обязан анализировать контекст аргументов, чтобы отличить визуально похожие, но семантически разные сущности (полиморфизм нотации).

### Пример: Символ $f^{-1}$

**Сценарий А: Обратная функция (Inverse Function)**
- **Контекст:** $f^{-1}$ используется самостоятельно или применяется к элементу кодомена ($y \in Y$).
- **Сигнатура:** $f: X \to Y \implies f^{-1}: Y \to X$.
- **Target Entity:** `op-inverse` (Operation).
- **Markup:** `\entityref{op-inverse}{f^{-1}}(y)`

**Сценарий Б: Полный прообраз (Preimage)**
- **Контекст:** $f^{-1}$ применяется к подмножеству кодомена ($B \subset Y$).
- **Сигнатура:** $f: X \to Y, B \in \mathcal{P}(Y) \implies f^{-1}(B) \in \mathcal{P}(X)$.
- **Target Entity:** `op-preimage` (Operation).
- **Markup:** `\entityref{op-preimage}{f^{-1}}(B)` (или `\entityref{op-preimage}{f^{-1}(B)}`, если токен включает скобки).

## 3. Структура Канонического Файла (File Template)

Каждый файл в `content/` должен строго следовать шаблону. Запрещен любой текст вне окружений, не соответствующих типам сущностей: `object`, `operation`, `property`, `theorem`, `axiom`.

```latex
% entity-id: {ID}
% entity-type: {TYPE}
% defined-in: {BOOK_REF} (optional metadata used for tracking origin)

\section{definition}
\label{entity:{ID}}

% 1. ОБЪЯВЛЕНИЕ ТИПОВ (Strict Typing Block)
% Все переменные должны быть введены через кванторы с указанием их множеств/пространств.
\forall\, \entityref{obj-set}{X}, \;\;
\forall\, \entityref{obj-function}{f \colon X \to X} \quad

% 2. ТЕЛО ОПРЕДЕЛЕНИЯ (Definitional Body)
% Левая часть (Definiendum) <==> Правая часть (Definiens)
% Использование \stackrel{\text{def}}{\Longleftrightarrow} для определений
% Использование \Longrightarrow для теорем
\entityref{prop-fixed-point}{x \text{ — неподвижная точка } f}
\stackrel{\text{def}}{\Longleftrightarrow}
x \in X \;\land\; f(x) = x \;\square
```

## 4. Процедура Заполнения (Workflow: Top-Down Expansion)

Процесс заполнения выполняется итеративно, двигаясь от сложных концепций к аксиомам.

### Phase 1: Source Selection & Prioritization (Выбор Источника)
**Правило Языка:** Весь естественный язык внутри файлов сущностей (связки, комментарии, пояснения) должен быть на **русском языке**. Если источник на английском, формулировка переводится.

### 4.1 Источники (Sources)
*   **Primary:** В. А. Зорич, "Математический анализ", Часть 1.
*   **Reading Utility:** Чтение из учебников реализовано при помощи утилиты `pdf_to_images`, которая преобразует страницы PDF в изображения для контекстного анализа.
*   **Auxiliary:** Фихтенгольц, Кудрявцев, Демидович (для примеров и альтернативных формулировок).
*   **Verification:** ISO 80000-2, NIST DLMF, Encyclopedia of Mathematics (для выбора символов).
*   **Verification (Logic & Axioms):**
    1.  Vereshchagin, N.K., Shen, A. — *Languages and Calculi* (Языки и исчисления) [2012] — (Pri: High).
    2.  Mendelson, E. — *Introduction to Mathematical Logic* [1971].
    3.  Enderton, H.B. — *A Mathematical Introduction to Logic* [2001].
*   **Secondary (EN):** Rudin W. — *Principles of Mathematical Analysis* (Эталон краткости и строгости).
*   **Secondary (EN):** Apostol T.M. — *Calculus*.
*   **Secondary (RU):** Фихтенгольц Г.М. — *Курс дифференциального и интегрального исчисления* (Только если нигде больше нет подробностей, требует формализации).

**Алгоритм Выбора (Selection Algorithm):**
1. Ищем формулировку в источнике $N=1$.
2. **Fallback Condition:** Переходим к источнику $N+1$, если в текущем:
   - Сущность отсутствует.
   - Определение дано только словесно (verbally), без формул.
   - Определение "нестрогое" или упоминается мимоходом (mentioned in passing).
   - Определение опирается на неопределенные "интуитивные" понятия, которые раскрыты лучше в следующем источнике.
3. При нахождении подходящей строгой формулировки — используем её (переводим на русский при необходимости).
4. Метаданные `defined-in`: Указываем источник, откуда реально взята формулировка.

### Phase 2: Extraction & Normalization (Извлечение)

Для каждой сущности (объекта, операции, свойства):

1. **De-contextualize:** Удалить вводные слова ("Очевидно", "Рассмотрим", "Заметим, что"). Оставить только логический каркас.
2. **Variable Typing:** Выписать все переменные ($f, \xi, P$). Найти их типы и области определения в тексте учебника.
3. **Tokenization & Symbol Selection:**
   - Найти все математические объекты.
   - **Выбор Символа (Symbol Selection):**
     - Проверять общепринятые обозначения через авторитетные источники (в порядке приоритета):
       1. **ISO 80000-2** (Mathematical signs and symbols).
       2. **NIST Digital Library of Mathematical Functions (DLMF)**.
       3. **Encyclopedia of Mathematics** (Springer & EMS).
       4. **Документация LaTeX** (пакеты `amsmath`, `amssymb`).
   - Использовать этот символ для создания семантического макроса в `mathesis.sty` (см. п. 9.3).
   - Классифицировать токены по таблице из п. 1.
   - Разрешить перегрузки по п. 2.
4. **Ref Linking:**
   - Для каждого объекта проверить наличие ID в базе.
   - Если ID нет → добавить в список **"TODO Queue"**.
5. **Output:** Создать `.tex` файл в `content/`.

### Phase 3: Recursion (Рекурсия)
- Взять следующий ID из **"TODO Queue"**.
- Найти его определение в "Учебнике-Оракуле" (используя предметный указатель).
- Повторить Phase 2.
- **Критерий остановки:** Сущность является аксиомой или примитивом (`obj-set`, `logic-and`).

## 5. Валидация и QA

После создания файла необходимо выполнить следующие проверки:

1. **Compilation Check (Обязательная компиляция):** После завершения пакета изменений необходимо запустить компиляцию корневого файла `content/master.tex`. Код обязан собираться без ошибок (`Zero Compile Errors`).
2. **Ref Existence:** Все `\entityref{ID}{...}` ссылаются на существующие файлы или файлы в очереди.
3. **No Loops:** Отсутствие циклических зависимостей внутри определений сущностей (А ссылается на Б, Б ссылается на А).
4. **Logical Verification:** Ручная или перекрестная проверка файла на отсутствие логических разрывов. Убедиться, что формальная запись полностью соответствует смыслу исходной формулировки.

## 6. Обработка неявной информации и стандарты полноты (Edge Cases & Completeness)

В учебниках часто опускаются детали, считающиеся "очевидными". В базе знаний они должны быть восстановлены явно.

- **Явные ограничения (Explicit Constraints):** Если сущность вводится в контексте, который налагает на неё ограничения (например, "пусть $f$ — непрерывная функция"), это свойство должно быть прописано явно через конъюнкцию или типизацию.
  - ❌ **Плохо:** `$\forall f \dots$` (подразумевая непрерывность).
  - ✅ **Хорошо:** `$\forall \entityref{obj-function}{f}, \entityref{prop-continuous}{f \text{ непрерывна}}$`.
- **Полное наименование (Full Canonical Naming):** Определяемый термин в левой части формулы должен быть записан полностью, в соответствии с общепринятым математическим стандартом.
  - ❌ **Плохо:** $f$ называется равномерно непрерывной, если...
  - ✅ **Хорошо:** `$f$ называется $\entityref{prop-uniformly-continuous}{\text{равномерно непрерывной функцией на множестве } X}$`, если...
- **Коллизия имен:** Если $x$ используется и как вектор, и как скаляр в одной формуле → переименовать переменную ($x \to \vec{x}$).
- **Скрытые кванторы:** Фразы вида "$f(x) > 0$" подразумевают $\forall x$. Квантор должен быть восстановлен.
- **Reference Loop (Self-Reference):** В определении сущности, сам определяемый термин (LHS) не должен быть обернут в `\entityref`, указывающий на этот же файл. Используйте чистый LaTeX или спец. макрос `\entitydef`.
- **Header Naming (Наименование Заголовка):**
  - Заголовок секции (`\section{...}`) обязан содержать **развернутое наименование сущности** из учебника-источника, без сокращений и аббревиатур.
  - **Fallback:** Если в текущем учебнике используется сокращение или название отсутствует, необходимо найти полное общепринятое название в следующем по приоритету учебнике (см. п. 4.1).

## 7. Стандарты Доказательств (Proof Standards)

Для файлов типа `theorem` или `lemma`:

1. **Запрет на "Очевидно":** Использование фраз "очевидно", "легко видеть", "следует из вышесказанного" запрещено.
2. **Атомарность шагов:** Каждое логическое утверждение должно быть разбито на минимальные шаги вывода.
3. **Явные ссылки:** Каждый шаг доказательства, опирающийся на теорему или определение, должен содержать `\entityref` на соответствующую сущность.
4. **Логическая непрерывность:** Не допускается пропуск логических переходов. Если переход требует промежуточной леммы, она должна быть создана и сослана.

---

## 8. Стандарты Свойств (Property Standards)

Для файлов типа `property`:
1. **Доказуемость:** Свойства (как и теоремы) могут и должны содержать доказательства, если они не являются аксиоматическими.
2. **Структура:**
   - Если свойство является непосредственным следствием определения, доказательство может быть кратким.
   - Если свойство фундаментально (как коммутативность алгебры множеств), оно выносится в отдельный файл.

## 9. Версионирование и Замена Канонических Формулировок

Каноническая база строится итеративно по нескольким учебникам. По мере расширения возможны два типа изменений:

### Тип А: Замена формулировки (маловероятно)
Канонические формулировки из Учебника-Оракула могут быть заменены на формулировки из других учебников, если новая формулировка строже, полнее или лучше вписывается в граф зависимостей.

- **Правило:** Заменяемый файл сохраняет свой `entity-id`. Метаданные `defined-in` обновляются. Старая формулировка может быть сохранена в комментарии или в отдельном файле-варианте.

### Тип Б: Замена нотации (весьма вероятно)
Записи сущностей могут быть заменены на более общепринятые обозначения при добавлении материала из других источников.

- **Правило:** `entity-id` остаётся стабильным. Все `\entityref{ID}{...}` продолжают работать, т.к. привязаны к ID, а не к нотации. Обновляются только визуальные тексты внутри `\entityref{...}{ТЕКСТ}`.
- **Следствие для дизайна:** ID сущностей должны быть семантическими (`op-inverse`, `prop-continuous`), а не нотационными (`f-inverse`, `epsilon-delta`). Это обеспечивает устойчивость графа к изменениям нотации.

## 9. Технические Стандарты Проекта

### 9.1 Структура `master.tex`
- Структура документа должна строго соответствовать структуре директорий `content/` (Foundations, Objects, Operations, Properties, Theorems).
- Используется `\chapter` для категорий верхнего уровня и `\section` для сущностей.

### 9.2 Стилизация
- **Гиперссылки:** Использовать классический синий цвет (`colorlinks=true, linkcolor=blue, urlcolor=blue`) для лучшей видимости.
- **Оглавление:** Включать ссылки в оглавление (`linktoc=all`).

### 9.3 Семантические Макросы (mathesis.sty)

Все повторяющиеся математические обозначения должны быть вынесены в пакет `mathesis.sty`. В файлах контента запрещено использовать "сырой" LaTeX для математических идиом.

**Принцип:** `\newcommand{\SelfDescribingID}{LaTeX}`

**Примеры:**
```latex
% Sets
\newcommand{\mReal}{\mathbb{R}}
\newcommand{\mNatural}{\mathbb{N}}
\newcommand{\mEmpty}{\varnothing}

% Logic
\newcommand{\mImplies}{\Longrightarrow}
\newcommand{\mIff}{\Longleftrightarrow}
\newcommand{\mForall}[1]{\forall \, #1 \colon \quad}

% Analysis
\newcommand{\mSeq}[1]{\{ #1_n \}}
\newcommand{\mAbs}[1]{\lvert #1 \rvert}
\newcommand{\mNorm}[1]{\lVert #1 \rVert}
```

В файле контента используется: `\entityref{obj-real-numbers}{\mReal}`.
Это позволяет глобально менять нотацию (например, $\epsilon$ на $\varepsilon$) в одном месте.

### 9.4 Человекочитаемые Заголовки (Human-Readable Titles)
В `master.tex` (и соответственно в `\section{...}` внутри файлов контента) должны использоваться **полные наименования сущностей** на естественном языке (русском), а не технические токены.

*   **Правильно:** `\section{Отрицание}`, `\section{Предел функции}`
*   **Неправильно:** `\section{definition}`, `\section{prop-limit}`

Для доказательств используется `\subsection*{Доказательство}`.
